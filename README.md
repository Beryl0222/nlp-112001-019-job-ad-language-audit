# 校园招聘文本中的资格暗示核查

模拟招聘审阅资料采用 UTF-8 编码，人物、单位和记录均为合成内容。

| 资料 | 字段 |
| --- | --- |
| `资料/岗位来稿.json` | `id`、`employer`、`role`、`location`、`text` |
| `资料/共享稿.json` | `id`、`roles`、`channel`、`text` |
| `资料/更正与审核口径.json` | `id`、`source`、`text` |

每份资料是 JSON 数组。记录中的字段值按来源原样保留为字符串，逗号和顿号可以属于字段内容。资料中可能有转述、不同的拼写以及较晚录入的更正。数字及日期在这些文件中沿用各资料自身的含义；原文位置以记录编号及文本范围定位。

Node.js 22 环境下运行以下命令可安装锁定的项目环境、检查素材格式并读取各类资料的数量。

```sh
npm ci --offline --ignore-scripts --no-audit --no-fund
npm test
npm run materials
```

`readMaterials` 只读取资料，不解析其中的正文含义。

## 资格暗示核查工具

`audit/` 在读取层之上做纯文字核查，不收集任何求职者资料，也不代替学校作录用决定；所有结论都是带出处的审核建议。

| 模块 | 职责 |
| --- | --- |
| `audit/classify.js` | 按中文句读切分条款，依据语言标记区分类别：强制资格、偏好、举例、可补足条件、待遇说明、实际入口限制、适用范围/例外、术语释义、历史信息、指引性说明等；同时标注否定与转折 |
| `audit/reconcile.js` | 按雇主与岗位归并来稿、共享稿和更正；解析雇主澄清消除了哪项歧义；核对报名入口与当前公开说明是否一致；区分历史条件与本期条件；登记近似词在不同雇主处的含义；还原暂缓经过 |
| `audit/report.js` | 输出内部审核报告与面向学生的当前资格视图（只含当前资格、偏好及出处，不含暂缓结论） |
| `audit/cli.js` | 命令行入口，只读取模拟资料目录，不接收求职者输入 |

运行方式：

```sh
npm run audit            # 中文文本报告
npm run audit:json       # 结构化 JSON，便于渠道维护方按条目修改
node audit/cli.js --dir /path/to/资料 --out report.txt
```

### 核查口径

- 正文的“优先”是偏好而非门槛；“可入职后补修”是可补足条件，不等于必须持证。
- 报名须知、渠道维护方反馈里的实际入口限制才是学生能否申请的真实约束；正文已改而入口未同步时，限制并未解除。
- 否定、转折、例外（如“仅适用于”“只保留”“不要求”）按其字面收窄或否定资格，不反向推断。
- 近似词（如“项目经历”“结业”“证书”）按各雇主原文分别登记，释义只对该雇主有效；“另一家岭云”与“岭云工艺”不共享术语含义。
- 往年问答等历史条件标记为“不沿用”，只用于还原暂缓背景，不自动套用到本次。
- 共享模板按澄清后的实际范围核对：共用资格变成部分岗位门槛时，公共摘要与各岗位入口分别列出待改措辞。
- 依学校口径 r1：入口实际限制与当前公开说明不一致时，受影响岗位暂缓；已澄清且入口相容的岗位可发布。
- 每条结论附 `资料名 + 记录编号 + 字符区间`，可回到原文复核。
